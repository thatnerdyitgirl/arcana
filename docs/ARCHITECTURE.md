> Версия 0.2 · черновик на согласование · до написания кода

---

## 0.0 Главный принцип: у карты нет единственного значения

> **A card has no single universal meaning.**
>
> `MEANING = CARD × POSITION × QUESTION × CONTEXT × SURROUNDING CARDS`

Поэтому база устроена **не** как `карта → значение`, а так:

```
карта
 ├── VISUAL_FACT              что буквально изображено (+ uncertain, NOT_ESTABLISHABLE)
 ├── SOURCE_INTERPRETATION    что говорит каждый источник — по одному утверждению, с id источника
 ├── TRADITIONAL_MEANING      базовая линия традиции колоды
 ├── ARCANA_SYNTHESIS         авторские гипотезы: психология · отношения · работа · тень · вопросы · действия
 │                            (каждая гипотеза: status, basis, applies_when, not_mandatory)
 ├── POSITIONAL_APPLICATION   синтез, применённый к ТИПУ позиции; × тема вопроса (опционально)
 ├── EDITORIAL_NOTE           правки владельца — отдельная метка
 ├── modifiers                как смысл сдвигают соседние карты (движок сочетаний)
 └── guards                   RECOGNITION · COMMON_MODEL_ERRORS · WHAT_THIS_CARD_IS_NOT · tone_guards
```

**Метки слоёв обязательны и видны пользователю в «глубже»:** «Изображение» / «Источник: …» / «Традиция» / «Синтез Arcana» / «Заметка редактора». Синтез Arcana никогда не подаётся как «значение карты».

Правила движка:
- Ни один текст толкования не выдаётся без **позиции**. Даже «карта дня» имеет позицию: `theme_of_day`.
- Тема и контекст вопроса выбирают, **какие** слои активны. Например, в вопросе о работе слой отношений не показывается, если его не запросили.
- Соседние карты могут **усилить, смягчить или переключить** проявление (см. §3). Отдельное поле «значение карты» без этих множителей существует только как справочный слой в библиотеке.
- Формулировки в `position_manifestations` — это **возможные** проявления («может говорить о…»), а не утверждения.

> Миграция выполнена: 5 тестовых карт Манары переведены на схему 0.3 с этими слоями.
> Формат id: для Манары принят `MANARA_MAJOR_09`, `MANARA_AIR_06`; для RWS — `RWS_MAJOR_09`, `RWS_SWORDS_03` (раздел 2 ниже ещё показывает старый формат `rws.major.09`).

## 0. Принципы, которые зашиты в архитектуру

| Принцип | Как он выражен технически |
|---|---|
| У карты нет единственного значения | Смысл = карта × позиция × вопрос × контекст × соседние карты (§0.0) |
| Таро — инструмент рефлексии, не прогноз | В текстах нет будущего времени в утвердительной форме («случится»). Используются формы «может указывать», «тенденция», «тема». Есть проверка-линтер текстов базы на запрещённые формулировки. |
| Не выдумывать | Каждое утверждение в базе имеет `type`: `documented` / `tradition` / `synthesis` / `observed` и ссылку на источник. Приложение может показать, откуда взялся смысл. |
| Две системы колод не смешиваются | Отдельные папки, отдельные id (`rws.*`, `manara.*`), отдельные правила сочетаний. Общий только «скелет»: стихии, числа, типы позиций. |
| Факт ≠ интерпретация ≠ допущение | Модуль `grounding` и слой Reality check. Визуальный канон Манары делит поля на `observable` и `interpretation`. |
| Не поддакивать | В ответе нет оценок «ты права». Правила handoff-промпта прямо запрещают внешнему ИИ автоматически подтверждать версию пользователя. |
| Против компульсивности | Локальный детектор повторных вопросов. Мягкая подсказка, без стыда и без «успокойся». |

## 1. Общая карта знаний

```
                    ┌──────────────────────────┐
                    │        SHARED CORE        │  общее для всех колод
                    │ стихии · числа · позиции  │
                    │ темы · линзы · grounding  │
                    └────────────┬─────────────┘
                 ┌───────────────┴───────────────┐
        ┌────────▼────────┐             ┌────────▼────────┐
        │   RWS SYSTEM    │             │  MANARA SYSTEM  │
        │ карты (78)      │   НЕ        │ карты (78)      │
        │ визуальные      │ СМЕШИВАТЬ   │ VISUAL CANON    │
        │   заметки       │             │ (обязателен)    │
        │ пары/цепочки    │             │ пары/цепочки    │
        │ нумерация 8/11  │             │ своя нумерация* │
        └────────┬────────┘             └────────┬────────┘
                 └───────────────┬───────────────┘
                    ┌────────────▼─────────────┐
                    │         ENGINES          │
                    │ parser · spreads ·       │
                    │ combination · quint. ·   │
                    │ synthesis · handoff      │
                    └──────────────────────────┘
```
\* Проверено: в Манаре VIII — Справедливость, XI — Сила (марсельский порядок).

**Shared core** содержит только то, что одинаково работает в обеих системах:
- стихии мастей и правила взаимодействия стихий;
- значения чисел 1–10 как *структурный* слой (не нарративный!);
- типы позиций расклада (`blind_spot`, `influence`, `resource`…);
- темы (работа, отношения…) и словарь ключевых слов для их распознавания;
- философские линзы (Юнг, стоицизм, дао) как отдельная библиотека цитат и понятий;
- правила grounding (факт / интерпретация / допущение / страх / желание).

**Всё нарративное живёт внутри колоды.** Что «происходит» на карте, кто кому что делает, какое настроение — только `rws/` или только `manara/`.

## 2. Схема карты (Card Knowledge Model)

Одна карта = один JSON-файл. Полностью заполненный пример: `knowledge/rws/cards/major/09-hermit.json`.

```jsonc
{
  "id": "rws.major.09",            // deck.arcana.number | deck.minor.suit.rank
  "deck": "rws",                   // "rws" | "manara"
  "schema_version": "0.1",

  "identity": {
    "name_ru": "", "name_en": "", "aliases_ru": [],
    "arcana": "major|minor",
    "number": 0,                   // номер в ЭТОЙ колоде
    "roman": "",
    "suit": null,                  // wands|cups|swords|pentacles
    "rank": null                   // ace..10 | page|knight|queen|king
  },

  "correspondences": {             // каждая — с basis/type/source
    "element": {}, "astrology": {}, "hebrew_letter": {}, "number_value": {}
  },

  // RWS: visual_notes (символы с документированным смыслом)
  // MANARA: visual_canon (обязателен, см. §2.1)
  "visual": {},

  "upright": {
    "core": "",                    // 1–2 предложения, суть
    "psychology": "",              // внутренний процесс
    "shadow": "",                  // что не хочется замечать
    "contexts": {
      "relationships": "", "work": "", "money": "",
      "decision": "", "self": ""
    },
    "advice": "",
    "reflection_question": "",     // ОДИН вопрос
    "small_action": ""             // ОДНО действие в реальности
  },

  "reversed": {
    "mode": "blocked|excess|internalized|delayed",  // какой способ чтения
    "...": "те же поля, что upright"
  },

  "position_angles": {             // короткий угол карты под каждый тип позиции
    "blind_spot": "", "influence": "", "resource": "",
    "obstacle": "", "advice": "", "past": "", "present": "",
    "tendency": "", "self": "", "other": "", "hidden": ""
  },

  "lenses": {
    "jung":  { "archetype": "", "process": "", "type": "synthesis", "source": [] },
    "stoic": { "principle": "", "quote_paraphrase": "", "source": [] },
    "tao":   { "principle": "", "quote_paraphrase": "", "source": [] }
  },

  "traditional_meanings": {        // дословно из public-domain источников
    "waite_1910": { "upright": "", "reversed": "", "verified": false }
  },

  "common_misconceptions": [],     // что люди обычно думают неверно
  "common_model_errors": [],       // что ИИ-модели обычно путают
  "tone_guards": [],               // чего НЕ говорить с этой картой

  "sources": [],                   // id из knowledge/sources/registry.json
  "confidence": { "overall": "low|medium|high", "by_field": {} },
  "review": { "status": "draft|reviewed|verified", "reviewed_by": null, "date": null }
}
```

### Почему так
- **`position_angles` — главное поле для живого текста.** Не «Отшельник значит X», а «Отшельник в позиции *что я не замечаю* звучит как Y». Позиции любого расклада, в том числе пользовательского, мапятся на эти типы, поэтому кастомные расклады работают автоматически.
- **`reversed.mode`.** Перевёрнутые карты в разных школах читаются по-разному: заблокированная энергия, избыток, уход внутрь или задержка. Мы явно фиксируем, какой режим используется для каждой карты, вместо того чтобы просто писать «противоположное значение».
- **`tone_guards`** защищают от вредных шаблонов, например «Смерть — кто-то умрёт» или «Башня — всё рухнет».

### 2.1 Manara — `visual_canon` (обязательное поле)

```jsonc
"visual": {
  "kind": "manara_visual_canon",
  "verification": {
    "status": "unverified|observed_from_photo|verified_by_owner",
    "photo_ref": "manara/visual-canon/photos/<id>.jpg",  // приватно, не публикуется
    "verified_by": null, "date": null
  },
  "observable": {                     // ТОЛЬКО то, что видно глазами
    "characters_count": null,
    "characters": [
      { "ref": "A", "apparent_gender": "", "apparent_role": "",
        "body_position": "", "gesture": "", "gaze": "",
        "clothing": "", "holding": [] }
    ],
    "setting": "",
    "proximity": "",                  // расстояние между фигурами
    "contact": "",                    // есть ли физический контакт и какой
    "action": "",
    "objects": [],
    "composition": "",                // кто выше/ниже, кто в центре, кадрирование
    "color_and_light": ""
  },
  "interpretation": {                 // выводы — отдельно и с пометкой
    "power_dynamics": "",
    "emotional_atmosphere": "",
    "symbols": [ { "detail": "", "reading": "", "type": "synthesis|tradition" } ]
  },
  "common_model_errors": []           // «модели часто описывают здесь двух людей — на карте один»
}
```

**Правило движка:** текст интерпретации Манары может ссылаться на визуальную деталь только если она есть в `observable` и `verification.status ≠ unverified`. Иначе деталь не упоминается.

**Откуда берём визуальный канон (важно):** у меня нет проверенного доступа к изображениям Манары, и описывать их по памяти — прямой путь к галлюцинациям. Поэтому процесс такой:
1. Ты фотографируешь каждую карту своей физической колоды.
2. Я по фото заполняю `observable` (статус `observed_from_photo`).
3. Ты сверяешь с картой и ставишь `verified_by_owner`.
4. Фото хранятся приватно и в приложение не публикуются, потому что арт защищён авторским правом. В базе остаётся только наше словесное описание.

## 3. Движок сочетаний (Combination Engine)

Работает в два прохода: **детекторы** находят паттерны, а **ранжировщик** выбирает 1–3 самых значимых для краткого ответа. Остальное уходит в «глубже».

### 3.1 Детекторы

| # | Детектор | Что считает | Тип знания |
|---|---|---|---|
| 1 | `pair` | Совпадение по таблице пар `A+B` (порядок не важен, либо важен — флаг `ordered`) | documented / synthesis (помечено) |
| 2 | `sequence` | Нарратив `A → B → C` по шаблонам: *нарастание*, *разрешение*, *поворот*, *петля* | synthesis (правила документируем) |
| 3 | `suit_repeat` | ≥2 карты одной масти (≥50% расклада = доминанта) | tradition |
| 4 | `number_repeat` | Одинаковые числа (две 3, три 7) и числовые семьи (9 + XVIII → 9) | tradition |
| 5 | `major_density` | Доля старших; кластеры (подряд идущие старшие) | tradition |
| 6 | `element_balance` | Счёт Огонь / Вода / Воздух / Земля | tradition |
| 7 | `dominant_element` | Стихия > 50% или с перевесом ≥2 | tradition |
| 8 | `missing_element` | Отсутствующая стихия (значимо при ≥4 картах) | tradition |
| 9 | `suit_transition` | Переход стихий по позициям: Воздух → Вода → Земля | synthesis |
| 10 | `court_pattern` | ≥2 придворных: «много людей / ролей», одинаковый ранг (две Королевы), ранговая лестница | tradition |
| 11 | `elemental_dignity` | Соседние карты дружественны / враждебны по стихиям | documented (Golden Dawn) |
| 12 | `reversal_density` | Доля перевёрнутых (≥50% — «внутренний процесс / торможение») | tradition |

### 3.2 Элементальные достоинства (Golden Dawn, задокументировано)
- Огонь + Воздух — дружественные; Вода + Земля — дружественные.
- Огонь + Вода — враждебные; Воздух + Земля — враждебные.
- Одинаковые стихии усиливают друг друга.
- Огонь + Земля, Вода + Воздух — нейтральные.

Стихии **старших арканов** выводятся через астрологические соответствия Golden Dawn (Отшельник → Дева → Земля). Это соглашение одной традиции, поэтому оно помечено `tradition: golden_dawn` и может быть отключено в настройках.

Для Манары (проверено по печати на картах, см. `MANARA-DECK-SPEC.md`): числовые карты 2–10 используют те же деканы, что Golden Dawn. Но у старших арканов астрология привязана к номеру (VIII Справедливость = Лев, XI Сила = Весы), а Шут, Наказание и Суд получили Уран, Нептун и Плутон. Поэтому стихии старших арканов Манары по правилам Golden Dawn **не выводятся**, а придворные используют собственную схему (Рыцарь — мутабельный знак, Королева — кардинальный, Король — фиксированный).

### 3.3 Формат таблицы пар
```jsonc
// knowledge/rws/combinations/pairs.json
{
  "a": "rws.major.09", "b": "rws.minor.swords.03",
  "ordered": false,
  "when": { "a_reversed": null, "b_reversed": true },   // null = любая ориентация
  "theme": "…",
  "text": "…",
  "type": "documented|synthesis",
  "source": [], "confidence": "medium"
}
```
Правило: пары с `type: documented` требуют источник. Пары `synthesis` в интерфейсе подписываются «авторская связка Arcana», без авторитетного тона.

### 3.4 Ранжирование (что показать в кратком ответе)
Вес = значимость паттерна × редкость × связь с темой вопроса. Например, «нет Воды» в вопросе про отношения весит больше, чем в вопросе про деньги. В краткий ответ попадают максимум **2 паттерна**.

## 4. Модуль квинтэссенции

### 4.1 Что это
Квинтэссенция — «скрытая карта» расклада: сумма значений выпавших карт, приведённая к числу старшего аркана. Метод особенно распространён в русскоязычной практике и почти не встречается в классических англоязычных источниках (там есть близкий метод «карт рождения» — Mary K. Greer). **Единого канона нет**, поэтому методы хранятся как отдельные, явно названные варианты.

### 4.2 Параметры метода
Любой метод описывается набором параметров, чтобы различия между школами были видны, а не спрятаны:

```jsonc
{
  "id": "q.digit_sum_22",
  "name_ru": "Сумма с редукцией цифр (до 22)",
  "include": "all|majors_only",
  "values": {
    "major": "number",                 // аркан = свой номер в колоде
    "fool": 0,                          // 0 | 22
    "ace": 1, "pips": "face",
    "court": "zero|page11_14|excluded"  // придворные: 0 / Паж=11…Король=14 / не учитываются
  },
  "reversed_affects": false,
  "reduction": "digit_sum|subtract_22|subtract_21",
  "reduce_while": "> 22",               // или "> 21"
  "result_22": "fool|keep_22",
  "result_0": "fool|none",
  "numbering": "deck",                  // 8/11 по колоде: в RWS 8 = Сила, 11 = Справедливость
  "sources": [], "confidence": "low"
}
```

### 4.3 Методы-кандидаты (все требуют сверки с источниками)

| id | Суть | Где встречается (проверить) |
|---|---|---|
| `q.digit_sum_22` | Сумма всех карт; если > 22 — складываем цифры, пока не станет ≤ 22. 22 = Шут. | Наиболее распространённый в русскоязычных школах |
| `q.subtract_22` | Сумма; если > 22 — вычитаем 22, пока не станет ≤ 22. | Альтернативный вариант в ряде школ |
| `q.majors_only` | Считаются только старшие арканы | Встречается как упрощённый вариант |
| `q.greer_birth_style` | Редукция цифр до ≤ 21 (метод карт рождения) | Mary K. Greer, адаптировано к раскладам — помечаем как «адаптация» |

Как придворные учитываются в квинтэссенции (0, 11–14 или вообще не учитываются) — **главная точка расхождения школ**. Это нужно подтвердить источниками, прежде чем ставить какой-то вариант по умолчанию.

### 4.4 Что видит пользователь
```
Отшельник 9 + Тройка мечей 3 + Звезда 17 = 29
Метод: сумма цифр → 2 + 9 = 11 → XI Справедливость
(другой метод, −22: 29 − 22 = 7 → VII Колесница)  [свернуто]
```
Роль квинтэссенции в тексте: **«общая тема или ресурс расклада»**, а не «итог» или «ответ». Она подаётся одной строкой после синтеза.

## 5. Схема раскладов

```jsonc
{
  "id": "spread.self.what_to_see_now",
  "name_ru": "Что мне важно увидеть сейчас?",
  "theme": ["self", "decision", "any"],
  "purpose": "Подсветить слепое пятно, влияющий фактор и ресурс",
  "card_count": 3,
  "positions": [
    { "n": 1, "name_ru": "Что я сейчас не замечаю?", "type": "blind_spot",
      "description": "То, что уже есть в ситуации, но вне фокуса внимания" },
    { "n": 2, "name_ru": "Что влияет на ситуацию?", "type": "influence",
      "description": "Внешний или внутренний фактор, который сейчас формирует происходящее" },
    { "n": 3, "name_ru": "Что мне поможет?", "type": "resource",
      "description": "Внутренний ресурс или способ действия" }
  ],
  "question_type": ["open", "self_inquiry"],   // НЕ "yes_no", НЕ "will_he"
  "decks": ["rws", "manara"],
  "logic": {
    "reading_order": [1, 2, 3],
    "key_relation": "1→3: от слепого пятна к ресурсу",
    "synthesis_template": "blind_spot_to_resource"
  },
  "origin": "user|arcana|tradition"
}
```

- **Пользовательский расклад:** пользователь пишет название и позиции своими словами, а парсер предлагает тип позиции («Что мешает?» → `obstacle`). Пользователь подтверждает одним тапом.
- **Каталог (следующий этап):** около 3 раскладов на каждую из 11 тем, примерно 33 расклада. Твои расклады идут с `origin: user` и в приоритете.
- **`question_type`** нужен для мягкой переформулировки. Если вопрос выглядит как «вернётся ли он», приложение предлагает расклад про себя в этой ситуации, но не запрещает расклад.

## 6. Парсер естественного языка

### 6.1 Конвейер
```
сырой текст
 → нормализация (нижний регистр, ё→е, «—»/«-» → разделитель, лишние пробелы)
 → разделение: часть с картами | часть с контекстом
     (эвристика: после «—», «про», «по поводу», «вопрос:» и т.п. идёт контекст)
 → токенизация карт (по запятым, «;», переносам, «и»)
 → распознавание каждой карты:
     1. точное совпадение по словарю алиасов
     2. шаблон «ранг + масть»
     3. fuzzy-совпадение (расстояние Левенштейна ≤ 2 для слов > 5 букв)
 → маркеры переворота
 → определение колоды (настройка по умолчанию, или слово «манара»/«уэйт» в тексте)
 → определение темы и типа вопроса по контексту
 → результат + список неоднозначностей
```

### 6.2 Словари (`knowledge/parser/aliases.ru.json`)
- **Ранги:** `1|туз|ace` · `2|двойка|2ка|II` … `10|десятка|X` · `паж|валет|принцесса` · `рыцарь` · `королева|дама` · `король`
- **Масти:** `мечи|меч|мечей|М` · `кубки|кубок|чаши|чаш|К` · `жезлы|жезл|посохи|скипетры|Ж` · `пентакли|пентакль|денарии|монеты|диски|П`
- **Переворот:** `перев|перевернутая|перевернутый|пер|↓|(п)|rev|r` — до или после названия карты
- **Старшие:** все русские и английские названия, номера (`IX`, `9 аркан`) и разговорные формы (`повешенный`, `висельник`)

### 6.3 Неоднозначности — переспросить, а не угадывать
- `3К` → кубки или… (в некоторых колодах «К» = королева). Приложение показывает чип «3 кубков?» с вариантами.
- `9` без масти → IX Отшельник или девятка какой-то масти?
- Короткий код `П` → пентакли или посохи? Это зависит от того, как называет масти конкретный человек. Запоминаем его выбор локально.
- Если контекст содержит имена или другие личные данные, они остаются в контексте и в handoff-промпт попадают только с явного согласия пользователя.

### 6.4 Результат парсера
```jsonc
{
  "deck": "rws",
  "cards": [
    { "raw": "Отшельник", "id": "rws.major.09", "reversed": false, "confidence": 1.0 },
    { "raw": "3 мечей перев", "id": "rws.minor.swords.03", "reversed": true, "confidence": 1.0 },
    { "raw": "Звезда", "id": "rws.major.17", "reversed": false, "confidence": 1.0 }
  ],
  "context_raw": "про работу, не понимаю, уходить или нет",
  "topic": { "value": "work", "confidence": 0.9 },
```

## 7. Конвейер интерпретации

| Шаг | Что делает | Виден сразу? |
|---|---|---|
| 1. Вопрос и контекст | Парсер, тема, тип вопроса; детектор повторов | — |
| 2. Колода | Выбор системы; дальше только её данные | — |
| 3. Расклад и позиции | Тип каждой позиции | заголовки позиций |
| 4. Карта в позиции | `position_angles[type]` + контекст темы | **да, 2–3 фразы на карту** |
| 5. Сочетания | Детекторы §3 | **1–2 паттерна одной строкой** |
| 6. Масти и стихии | Баланс, доминанта, нехватка | в «глубже» |
| 7. Числа | Повторы, числовые семьи | в «глубже» |
| 8. Плотность старших | Доля старших и кластеры | в «глубже» (или 1 строка, если ≥ 2/3) |
| 9. Квинтэссенция | Метод из настроек | **одна строка** |
| 10. Линза | Выбор Юнг / стоики / дао по теме и картам | в «глубже» |
| 11. Синтез | Связный абзац по шаблону расклада | **да** |
| 12. Один вопрос | Из `reflection_question` ключевой карты + адаптация к позиции | **да** |
| 13. Одно действие | `small_action` ключевой карты, приземлённое к теме | **да** |
| — | Reality check: факт / интерпретация / допущение / страх / желание | за кнопкой |
| — | «Углубить в чате» | кнопка |

**Выбор линзы:** если тема про контроль, тревогу или чужие действия, берём стоиков (дихотомия контроля). Если человек давит, торопит события или борется с потоком — дао. Если речь об идентичности, повторяющихся сценариях или Тени — Юнга. Пользователь может переключить линзу.

**Сборка текста.** Без ИИ текст собирается из кусочков базы по шаблонам с правилами согласования, чтобы не получался набор отдельных предложений. У каждого шаблона есть 3–5 вариаций, чтобы ответы не звучали одинаково.

**Grounding-правила для всех текстов:**
- нет утверждений о мыслях и чувствах другого человека: «он думает» → «карта может отражать то, как ты считываешь его поведение»;
- нет предсказаний в утвердительной форме;
- нет слов «успокойся», «расслабься», «делулу», «ты должна»;
- серьёзные решения: одна ненавязчивая строка «карты — один из взглядов на ситуацию, не основание для решения сами по себе».

**Повторные вопросы:** если похожий вопрос (та же тема + похожие слова) задаётся 3 раза за 7 дней, перед раскладом появляется строка: «Ты возвращаешься к этому вопросу уже третий раз. Хочешь посмотреть, что изменилось с прошлого раза?» Тап показывает прошлые расклады рядом. Расклад не запрещается.

## 8. Формат передачи во внешний ИИ (handoff)

Две части: структурированные данные и готовый текст-промпт. Копируется текст, а данные сохраняются для истории.

```jsonc
{
  "handoff_version": "0.1",
  "created_at": "2026-10-02T12:00:00Z",
  "reading_mode": "self|client",
  "deck": { "id": "rws", "name": "Rider-Waite-Smith" },
  "question": { "original": "", "context": "", "topic": "work", "question_type": "decision" },
  "spread": { "id": "", "name": "", "positions": [ { "n": 1, "name": "", "type": "" } ] },
  "cards": [ { "position": 1, "id": "", "name_ru": "", "reversed": false } ],
  "arcana_reading": {
    "per_card": [ { "position": 1, "text": "" } ],
    "combinations": [ { "detector": "", "text": "", "type": "" } ],
    "suits": {}, "elements": { "fire": 0, "water": 0, "air": 0, "earth": 0, "dominant": null, "missing": [] },
    "numbers": {}, "major_density": { "count": 0, "ratio": 0 },
    "quintessence": { "method": "", "calculation": "", "result_id": "", "text": "" },
    "lens": { "id": "", "text": "" },
    "synthesis": "",
    "reflection_question": "", "small_action": ""
  },
  "user_notes": "",
  "unresolved_question": "",
  "instructions_for_model": "см. ниже"
}
```

**Блок инструкций для внешнего ИИ** (добавляется в конец промпта):
> Ты продолжаешь уже сделанный расклад таро. Не перетолковывай карты с нуля — опирайся на интерпретацию выше и углубляй её. Таро здесь — инструмент рефлексии, не предсказания: не утверждай, что что-то произойдёт, и не утверждай, что знаешь мысли или намерения других людей. Различай факты, интерпретации, допущения, страхи и желания. Не соглашайся с версией пользователя автоматически: если она похожа на тревожное мышление, катастрофизацию, подтверждение желаемого или поиск успокоения, мягко скажи об этом. Не стыди и не говори свысока. Задавай не больше одного вопроса за раз. Если речь о серьёзном решении, напомни, что карты — один из взглядов, а не основание. Отвечай на русском, без эзотерического пафоса.

## 10. Что можно безопасно писать как авторский синтез (с пометкой)
- `position_angles` — угол карты под тип позиции (на основе core-смысла);
- психологический слой, Тень, вопросы рефлексии, маленькие действия;
- связи с архетипами Юнга (Юнг не составлял систематического соответствия с таро — это интерпретационная традиция, например Sallie Nichols, *Jung and Tarot*, 1980);
- шаблоны цепочек `A → B → C` и переходов стихий;
- шаблоны синтеза и вариативные формулировки;
- правила тона и grounding.

## 11. Где RWS и Манара разделены полностью
- нарративные значения карт (`upright`, `reversed`, `contexts`, `position_angles`);
- визуальные описания (RWS — `visual_notes`, Манара — `visual_canon`);
- таблицы пар и цепочек;
- нумерация старших арканов (пока не проверена для Манары);
- стихии старших арканов (в Манаре выключены до проверки);
- примеры, линзы и вопросы рефлексии — у каждой карты свои, копировать между колодами нельзя;
- **общее только:** стихии мастей, структурные значения чисел, типы позиций, темы, правила grounding, движки.

Проверка в коде: валидатор запрещает ссылку из `manara/*` на `rws/*` и наоборот.

## Две колоды (2026-10-03)
Движок общий для Манары и RWS: `engine/core.mjs` хранит реестр колод (`DECKS`), карта несёт `deck`, `element`, `court`. Различия: RWS — перевёрнутые значения (`REVERSED`, режимы), контекстные линзы по карте (`context_lenses`), связи карт (`CARD_LINKS` → пары с типом); категорийные линзы Манары (`engine/lenses.mjs`) в RWS не применяются. Парсер строит отдельный индекс на колоду. Вытяжка — `engine/draw.mjs` (Web Crypto, без смещения). Подробности: `docs/RWS-KB-v1.md`.
